# Alert threshold settings (tab "Ambang Batas", tabel alert_thresholds)

Moved out of `AGENTS.md` (text unchanged) so that file stays short. Read this before changing the feature.

- `src/lib/dashboard/thresholds.ts`, `threshold-registry.ts`, `src/components/dashboard/threshold-settings.tsx`, tab "Ambang Batas" of `settings-board.tsx` (`/app/pengaturan`): the alert threshold settings (PRD "Atur Ambang Alert"), stored in table `alert_thresholds`. One card per rule in `anomalyRules` (queue, cpu, port, optical, offline): the threshold and the seconds the condition must last. `thresholds.ts` is pure: the defaults are READ from `anomalyRules` (`defaultThresholds`), never repeated, and the file owns only the allowed ranges (`thresholdLimits`: queue and cpu threshold 50-99 %, because "above 100 %" can never happen and 100 would silently switch the rule off; port 1-1000 error/menit; optical -40 to -15 dBm in steps of 0.5 with a fixed 0 s duration, alert at once; offline has no number, only 10-3600 s). Fields are free TEXT while typed (`parseNumberInput`: ASCII digits, one leading minus, one comma or dot as decimal, no `1e2`, `0x10`, plus sign, Arabic digits or trailing letters, and a thousands pattern such as `1.000` is REFUSED, never guessed, because JS would read it as 1); `evaluateTexts` gives the valid values plus per-field Indonesian errors, `validateThresholds` checks numbers (also used on stored data), `changedThresholds` lists `{kind, field, from, to}` in rule order and is the input the future "Jejak Aktivitas" (audit log) task should use, `describeRule`/`formatSeconds` write the sentence (minutes only when the seconds divide by 60, never rounds). `threshold-registry.ts` loads and writes `GET/PUT/DELETE /api/thresholds` (`thresholds.service.ts`; PUT/DELETE need `threshold:manage`, checked by the server), reading every answer through `parseThresholds` (a broken rule falls back to its default, `__proto__` and unknown keys are dropped). It is shaped for `useSyncExternalStore`: the snapshot is `{ values, status }` with status `loading`/`ready`/`error`; server snapshot = defaults + `loading`, so server HTML and first client render agree; it loads on the first subscriber and again on window `focus` (a save by another tab or operator shows up). Saving and "Kembalikan semua" are blocked until the stored values loaded, so defaults on screen never overwrite stored values; a failed load shows `threshold-load-error` with "Coba muat lagi", a refused or unreachable save shows `threshold-failed` and keeps the draft. The component keeps only the fields the user edited (`edits`), everything else shows the saved value, so there is no effect copying storage into state. All cards sit in ONE `<form noValidate data-testid="threshold-form">`: "Simpan ambang" is its only `type="submit"` button and Enter in any field submits through the same `handleSave` (blocked: nothing saved, focus moves to the first invalid field); every other button is `type="button"`, and the inputs are `type="text"` so the browser's own validation bubbles never replace the Indonesian messages. Buttons use `aria-disabled` with the reason as text (never `disabled`); "Kembalikan semua ke bawaan" uses `AlertDialog` and saves at once; the per-card reset only fills the draft. HONESTY: the Go rule engine reads `alert_thresholds` once at backend start (`backend/cmd/server/main.go`), so a change applies after a backend restart; the numbers do NOT change `anomalyRules`, the demo mock alerts or the Anomali page (a test saves CPU 60 and checks the Anomali page still says 85 %); the tab says so. The page-level "Simpan Perubahan"/"Reset Bawaan" buttons of `settings-board.tsx` do not cover this tab (other tabs still keep their old mock `noc_app_settings`, including the Telegram token and WhatsApp numbers in plain `localStorage`: do not treat that as a place for secrets). Known limit: no live reload in the Go engine (restart needed). `settings-board.tsx`'s `TabsList` needed `group-data-[orientation=horizontal]/tabs:h-auto`: the stock `h-9` made the wrapped tabs overlap the heading below at 390 and 768 px (`e2e/thresholds-ui.spec.ts` measures it). Tests: `e2e/thresholds.spec.ts` (pure: defaults equal `anomalyRules`, every range edge, text parsing, sentences, durations, changes, garbage in stored text, a seeded random comparison with an independent reference, the registry with a fake server; twelve mutations of the logic were each caught) and `e2e/thresholds-ui.spec.ts` (page: cards, save and reload, invalid input, cancel, per-card and global reset with the dialog and focus, server refusing/unreachable/failing to load, an account without `threshold:manage`, honesty text; signs in as admin and empties `alert_thresholds` before each test; 390/768/1440 px, contrast in both themes). E2E runs against the PRODUCTION build, so run `npm run build` after changing source or the test still sees the old page.

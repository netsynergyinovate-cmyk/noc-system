# Jejak Aktivitas (activity log page, mock data)

Moved out of `AGENTS.md` (text unchanged) so that file stays short. Read this before changing the feature.

- `src/lib/dashboard/audit.ts`, `src/components/dashboard/audit-board.tsx`, `src/app/(protected)/app/jejak-aktivitas/page.tsx`, menu item "Jejak Aktivitas" (right after "Pengaturan" in `app-nav.tsx`): the activity log page (PRD "Jejak Aktivitas": who changed what and when), mock data for now (`<MockDataNotice source="log audit di backend" />`). `audit.ts` is pure and holds the contract of a future `GET /api/v1/audit?limit=&before=` in its top comment: `actor` comes from the verified session (automatic events use `AUDIT_SYSTEM_ACTOR`), `at` is a WHOLE-second epoch from the server clock, newest first, never in the future, entries are append-only with stable ids. `loadAudit` is the seam (200 ms mock latency, fails with `AuditLoadError` while `navigator.onLine` is false, validates `limit` 1..500 and `before`); the window is 30 days (`at > now - 30 d` and `at <= now`, exact to the second), 20 rows per page (`pageAudit`, a bad size falls back to 20, buttons use `aria-disabled`), polled every 30 s through `usePolled`; a failed refresh keeps the last data and shows an alert with "Coba lagi" (`auditView` decides loading/error/empty/ready/stale). `mockAuditLog(now)` is a function of time only (4-8 entries per UTC day from `AUDIT_MOCK_START` 2025-01-01, five operators plus "Sistem" for `billing-sync`; before the start the log is empty, which is also how the empty state is tested), nine actions in the frozen `auditActions` table (label, lucide icon NAME, group; the component maps names to icons so the lib stays React-free). SECRETS NEVER ENTER THE LOG, in layers: a change to a secret field (Wi-Fi password, router password, bot token, API key) may only be `redacted(field)` = `{ field, redacted: true }` and the type forbids `from`/`to` on it (`never`); `changed()` refuses secret field names (`isSecretField`) and values that look like secrets (`findSecret`: password words, `token=`/`kata sandi=`, Bearer, Telegram bot token, `ngpk_`/`sk-`/`ghp_`/`AKIA` prefixes, credentials in URLs, any 32+ character random-looking run) without copying the value into the error; `buildAuditEntry` re-checks every text of an entry and every mock entry goes through it, and the backend must apply the same rules before writing to `audit_log` (`src/db/schema/audit-log.ts` already exists from the first database work; it was not touched). The table is a real `<table>` inside a focusable `role="region"` scroller (page itself never scrolls sideways; at 390 px the table scrolls inside its card). Tests: `e2e/audit.spec.ts` (pure: determinism, order, both window edges to the second, stable ids across shifting windows, no secrets in a year of entries, every secret pattern by name, paging against an independent reference over 3000 random cases, summaries, `loadAudit`; twelve mutations were each caught) and `e2e/audit-ui.spec.ts` (page: menu and `aria-current`, rows equal `mockAuditLog`, times to the second in two time zones, paging and focus, tiles equal the data, nothing secret in the DOM, loading/empty/error states, 390/1440 px, contrast in both themes). Search and filters (`src/lib/dashboard/audit-filter.ts` pure, `audit-filters.tsx` UI, state in `AuditLog`; component state, not URL state, like the alert history): free text where EVERY word must match (case-insensitive, NFC, any whitespace is one space, a word fragment is enough; a blank query is not an active filter) over what the row shows (operator name, action label, GROUP label such as "Perangkat", target, summary and each `describeChange` line; the entry id is never searched, and a secret field only matches by its NAME because no value exists), plus Aksi, Petugas (by operator id, "Sistem" last, an operator that dropped out of the data stays selectable with count 0) and Waktu (1 jam/24 jam/7 hari, `at > now - span && at <= now` exact to the second, measured from the start of the current minute through `useNowMinute`, so an entry made in the current minute joins "last hour" only when the minute turns). `matches`, `filterAudit` and `auditFacetCounts` share ONE checker (`matchesWith`), and every option shows how many rows picking it would leave with the other dimensions kept; changing any filter returns to page 1; no match shows "Tidak ada aktivitas yang cocok" with "Tampilkan semua aktivitas" (clears everything, focus to the search box); Escape clears the typed text; "Hapus saringan" is `aria-disabled` with its reason as text; the three tiles above stay whole-window numbers; `filterAudit` returns the SAME array when nothing is dropped so memo and renders do no extra work. Tests: `e2e/audit-filter.spec.ts` (pure, with a brute-force reference over 150 random filter states checking every option's count; 58 mutations tried by the agent and 11 more by me were all caught) and `e2e/audit-filter-ui.spec.ts` (page). Limits: no export and no `audit` resource in `permissions.ts` yet (any signed-in role can open the page, which only shows mock data; add `audit: ["read"]` with a server guard when the backend exists), the log is not yet fed by real events (threshold saves, "Tandai ditangani" and CPE changes do not write entries; `changedThresholds` in `thresholds.ts` is the ready input for the first), and the error state is driven by `navigator.onLine`, not by an HTTP status.

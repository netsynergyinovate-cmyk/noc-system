# Sign-in and sign-up pages

Moved out of `AGENTS.md` (text unchanged) so that file stays short. Read this before changing the feature.

- `src/components/auth-form.tsx`, `src/lib/auth-errors.ts`, `src/app/(auth)/layout.tsx`, `src/app/page.tsx`, `src/components/brand.tsx`: the sign-in and sign-up pages (Indonesian copy; from 1024 px a left panel with the NOC pitch and a static decorative chart, below that only the form). The form talks to the real Better Auth only: there are no demo accounts, no "demo login" button and no bypass, and no operational numbers (not even mock ones) on these public pages. `/` has no UI: it redirects a signed-in visitor to `/app` and anyone else to `/sign-in` (the answer is 200 plus a client redirect because the root `loading.tsx` wraps pages). `authFailureMessage` and `authFailureFocus` (`auth-errors.ts`, pure) are the only place that turns a failure (HTTP status plus Better Auth `code`, or a request that never arrived) into the Indonesian message and the field to focus; server text is never shown (it is English and changes between versions). Sign-in gives ONE message for every credential failure (unknown email, wrong password, anything else) so the page cannot be used to guess which emails exist; 429, network failure, server trouble (5xx, `INVALID_ORIGIN`, `MISSING_OR_NULL_ORIGIN`: the server is at fault, not the password) and `BANNED_USER` each have their own. The fields are inside a `fieldset disabled` while a request runs, which drops focus, so after a failure the form moves it by hand (the password field, selected, for bad credentials; the email field for an email already taken; the submit button otherwise) and marks that field `aria-invalid` with `aria-describedby` to the `role="alert"` message; one request at a time is enforced with a synchronous ref as well as `pending`. The password toggle keeps its name ("Tampilkan kata sandi") and flips `aria-pressed`. The form has `method="post"` so a submit that happens before the scripts load never puts the password in the URL. The left panel's headline is a paragraph, not a heading, so the page's only heading is the form's `h1`. Keep the tests' exact label queries (`getByLabel("Kata sandi", { exact: true })`): the toggle's name contains the same words. Tests: `e2e/login-page.spec.ts` (pure mapping against Better Auth's own error-code tables, structure, `/` redirects, 390/1024/1440 px, contrast in both themes, mocked server answers and focus, waiting state, toggle and Tab order, reduced motion, and the real server: unknown email versus wrong password must read identically, a banned account, an email already taken). Better Auth's rate limit (3 requests per 10 s per path) is real in these tests and is waited out, never disabled. Known limit to close before real data: sign-up is open (anyone who can reach `/sign-up` becomes a `user` and can open the dashboard). The login rate limit's client address is decided in `src/lib/auth-security.ts` (`ipAddressOptions`): without `TRUSTED_PROXIES` (comma-separated IPs or CIDRs in the environment, validated at start) EVERY forwarded header is ignored and all clients share ONE bucket per path (3 attempts per 10 s), so it cannot be sidestepped with a made-up `X-Forwarded-For`, but one client can briefly lock others out (the sign-in form then shows a countdown); behind your own reverse proxy set `TRUSTED_PROXIES` to the proxy so each operator gets a bucket, and keep the app reachable only through it. Sessions last 7 days and renew at most once a day, cookies are `httpOnly`, `SameSite=Lax`, `Path=/` (`e2e/auth-hardening*.spec.ts`).
